# MU5252 API Template

模板 ID：`MU5252`

匹配规则：

- `device.model_name == "MU5252"`
- 或 `device.hardware_version` 以 `MU5252_` 开头

当前对应实机：

- 展示名称：`TopFlow`
- `device_alias_name = "TOPFLOW"`
- `device_market_name = "TOPFLOW"`
- `device.hardware_version = "MU5252_HW1.0"`
- 平台：Qualcomm SDX75，OpenWrt 23.05.4

这个模板代表当前后端正式支持的 `TopFlow` 设备侧接口集合。它与 `MU5250` 的主要差异是双频 Wi-Fi、双卡流量查询参数，以及网络状态的 UCI 回退路径：

- Wi-Fi 在 `main_2g/main_5g` 中自动选择启用的主配置
- 实时流量调用必须携带当前 `current_sim_slot` 对应的 `subid`
- 网络信息优先读 `zte_nwinfo_api`；对象不可用时，把 `zte_nwinfo` UCI 的分区字段归一化成同一份网络快照
- CPU 温度直接使用 `zwrt_bsp.thermal get_cpu_temp` 的 `cpuss_temp`

## Field Mapping

| snapshot | source |
|----------|--------|
| `net.*` | 优先 `zte_nwinfo_api nwinfo_get_netinfo`；不可用时从 `zte_nwinfo` 的 `sys_info/signal_strength/cell_info/wan_active_band/plmn_info/band_lock` 分区归一化 |
| `net.wan_status` | `zwrt_router.api router_get_status_no_auth` |
| `wlan.ssid/key/enc/enabled` | `wireless.main_2g/main_5g` 自动选择：优先启用中的主 Wi-Fi，回退到第一个存在的主 Wi-Fi |
| `battery.*` | `zwrt_bsp.battery list`、`zwrt_bsp.charger list` 和 power-supply sysfs |
| `clients.total/wifi/lan` | `zwrt_router.api router_get_user_list_num` |

| `sms.unread/list` | `zwrt_wms_get_wms_capacity`、`zte_libwms_get_sms_data` |
| `nfc.switch` | `zwrt_nfc zwrt_nfc_wifi_get` |

| `qos.qci` / `qos.ambr_*` | 启动时扫描 `/data/logfs/key.log` 并缓存 |

| `system.uptime/mem_*` | `system info` |

| `device.*` | `get_zwrt_common_info`、`system board` 和后端模板选择结果 |

## Observed Notes

- 实机固件 `BD_ENCNMU5252V1.0.0B16` 上，`zte_topsw_nwinfo` 退出码为 `139`，因此没有注册 `zte_nwinfo_api`；`zte_nwinfo` UCI 仍保留完整的网络类型、信号、PLMN、频段和小区字段，已作为模板内的明确回退路径。
- `zwrt_data get_wwandst` 不带 `subid` 或传 `subid=0` 会返回 `Invalid argument`；当前活动卡槽为 `1`，携带 `subid=1` 后实时流量字段完整返回。后端会从 `get_sim_info.current_sim_slot` 更新活动 `subid`。
- 当前实机 `zwrt_bsp.thermal get_cpu_temp` 正常返回 `cpuss_temp`，无需启用 `thermal_zone` 回退。
- 设备同时提供 `main_2g` 和 `main_5g`，客户端回退接口也同时存在，因此沿用双频自动选择及 DHCP/路由列表回退策略。
