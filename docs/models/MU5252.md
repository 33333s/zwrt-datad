# MU5252 API Template

模板 ID：`MU5252`

匹配规则：

- `device.model_name == "MU5252"`
- 或 `device.hardware_version` 以 `MU5252_` 开头

当前对应实机：

- 展示名称：`TopFlow`
- `device_alias_name = "TOPFLOW"`
- `device_market_name = "TOPFLOW"`
- `device.hardware_version = "MU5252_HW1.0"`
- 平台：Qualcomm SDX75，OpenWrt 23.05.4

这个模板代表当前后端正式支持的 `TopFlow` 设备侧接口集合。实机不是单基带结构，而是一个集成 X75 加两个通过 USB CDC-ECM 接入 X75 的外挂 4G 基带：

- `x75`：集成 5G 基带，`rmnet_data0`，活动 `subid=1/2`
- `v3e1`：外挂 4G 基带，`V3E1net0` / `zte_mwan3`，活动 `subid=3/4`，USB `1-1`，ADB serial `V3E1T12345`
- `v3e2`：外挂 4G 基带，`V3E2net0` / `zte_mwan4`，活动 `subid=5/6`，USB `1-2`，ADB serial `V3E2T12345`

它与 `MU5250` 的主要差异是双频 Wi-Fi、多基带/多卡流量参数，以及网络状态的 UCI 回退路径：

- Wi-Fi 在 `main_2g/main_5g` 中自动选择启用的主配置
- 实时流量调用必须携带当前 `current_sim_slot` 对应的 `subid`
- 网络信息优先读 `zte_nwinfo_api`；对象不可用时，把 `zte_nwinfo` UCI 的分区字段归一化成同一份网络快照
- 两个外挂基带的网络、SIM、WWAN、流量、CDC-ECM 和 ADB 枚举状态统一输出到 `modems[1]` / `modems[2]`
- CPU 温度直接使用 `zwrt_bsp.thermal get_cpu_temp` 的 `cpuss_temp`
- X75 主机 thermal zones 直接读取 sysfs；V3E1/V3E2 通过固定 ADB serial 低频读取各自 `zte_power/adc2_temp`
- 聚合状态直接以 `zwrt_router.network.opms_wan_mode == SMULTIWAN` 为准
- 风扇与液冷控制由 datad 统一驱动并持久化到 `/data/zwrt-datad/cooling.conf`，不依赖 `/etc/init.d` 或 `/data/plugins/fan` 常驻脚本

## Observed Notes

- 实机固件 `BD_ENCNMU5252V1.0.0B16` 上观察到 `zte_topsw_nwinfo` 曾以退出码 `139` 退出，随后 procd 可重新拉起并恢复 `zte_nwinfo_api`；因此模板保留 UCI 回退，不能假设对象始终在线。
- `zwrt_data get_wwandst` 不带 `subid` 或传 `subid=0` 会返回 `Invalid argument`；当前活动卡槽为 `1`，携带 `subid=1` 后实时流量字段完整返回。后端会从 `get_sim_info.current_sim_slot` 更新活动 `subid`。
- 当前实机 `zwrt_bsp.thermal get_cpu_temp` 正常返回 `cpuss_temp`，无需启用 `thermal_zone` 回退。
- 两个 V3E 外挂系统没有标准 thermal/hwmon；厂商 `zte_power/adc2_temp` 连续采样稳定为摄氏度。`adc1_temp=124` 对应未接/查表上限，不作为有效温度源。
- 设备同时提供 `main_2g` 和 `main_5g`，客户端回退接口也同时存在，因此沿用双频自动选择及 DHCP/路由列表回退策略。
- 两个外挂基带运行 Linux 3.4/ARMv7 精简系统，本机没有 `ubus` 命令；全部 ubus 对象都在 X75 主机上注册，由 `at_server` 和 `zte_topsw_*` 汇总外挂基带数据。
- X75 实机共注册 135 个 ubus 对象。datad 的 `GET /ubus?verbose=1` 可返回完整运行时对象和方法签名；`POST /ubus/call` 可调用当前注册的全部方法，包括写方法。通用 `/control` 仍保留语义化白名单。
